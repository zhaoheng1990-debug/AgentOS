## Research Object

`PROVIDER_SUPPORTED_TRANSFORMATION_ATTRIBUTE_INFERENCE`

The Provider supports Runtime cognition by proposing typed semantic attributes
and binding each proposal to admitted evidence references. Runtime remains the
cognitive and decision subject: it validates the receipt, preserves missing
facts, compiles the relation, derives the action, and blocks invalid authority.

Object chain:

```text
Natural transformation description
  -> Provider-supported typed attribute receipt
  -> Runtime contract and evidence-reference validation
  -> deterministic transformation relation compiler
  -> Runtime action
```

Object-before-proxy declaration:

```text
ProviderSupportedTransformationAttributeInference
  -> exact five-attribute and witness-bound receipt
  -> joint attribute accuracy and Runtime action harm
```

## Leading Model

`M1_STRUCTURED_ATTRIBUTE_INFERENCE_ADEQUACY`

For fresh, materially specified transformation descriptions, one bounded
Provider batch can recover the five v0.3F attributes and bind them to admitted
evidence references accurately enough that deterministic Runtime compilation
produces no false deduplication.

Predictions:

1. each attribute has high exact accuracy;
2. most cases have an exactly correct five-attribute tuple;
3. all single-factor counterfactual pairs change the intended attribute;
4. Runtime action accuracy is high;
5. false deduplication is zero;
6. missing facts are represented as `UNKNOWN`, not invented certainty;
7. no Provider action or relation state enters canonical Runtime state.

## Rival Models

### M0_NATURAL_DESCRIPTION_UNDERDETERMINATION

The formal attributes cannot be recovered reliably from concise natural
descriptions. Errors should be broad and joint tuple accuracy should remain low
even when the private reference is mechanically coherent.

### M2_ATTRIBUTE_LABEL_COUPLING

The Provider recognizes familiar transformation labels rather than the causal
facts. It should fail counterfactual pairs in which the named operation remains
similar but uncertainty, target claim, lineage, or information preservation
changes.

### M3_WITNESS_DECORATION

Evidence references are decorative rather than grounding. The Provider should
emit invalid, missing, cross-case, or semantically unrelated references despite
plausible attribute labels.

### M4_BOUNDARY_ATTRIBUTE_BOTTLENECK

Errors should concentrate in `InformationRelation`, `AddedUncertainty`, and
`TargetClaimRelation`, indicating that source and lineage are inferable while
claim-relative equivalence remains too underdefined.

### M5_COMPILER_HARM_AMPLIFICATION

Small attribute errors can be amplified by deterministic compilation into false
deduplication. This rival is supported by any observed false
`DEDUPE_AND_COMBINE`, regardless of mean attribute accuracy.

## Causal Mechanism

The expected mechanism is constrained semantic decomposition:

```text
case-local evidence statements
  -> attribute-specific semantic comparison
  -> explicit evidence-reference binding
  -> Runtime validation
  -> ordered deterministic compilation
```

The Provider is not expected to reproduce Runtime policy. Its useful cognitive
contribution is reduction of the semantic possibility space before Runtime
applies the frozen decision boundary.

## Fresh Counterfactual Design

Create twelve cases as six pairs. Within each pair, change one decisive factor:

1. exact or bounded conversion versus material transformation error;
2. same target claim versus changed target claim;
3. information-preserving versus information-reducing transformation;
4. separate versus shared derivation pipeline;
5. explicit partial source relation versus unknown source relation;
6. verified versus unspecified transformation.

The public surface may contain only:

- case ID and target claim;
- source, lineage, transformation, uncertainty, and tolerance statements;
- admitted evidence-reference IDs;
- the five allowed attribute enums and their definitions;
- the required output schema.

It must not contain:

- private expected attributes;
- relation states;
- Runtime actions;
- pair identities or changed-factor labels.

## Runtime Authority Boundary

Provider output is limited to:

- case ID;
- five typed attributes;
- one or more admitted evidence references per attribute;
- missing-fact notes.

Provider output must not control:

- relation state;
- composition action;
- selection, retention, promotion, or baseline state;
- CoreSlim writes;
- claim-tolerance acceptance.

Runtime validates contract shape and evidence-reference membership, then invokes
the unchanged v0.3F compiler.

## Falsification Conditions

Reject or revise M1 if any occurs:

- any false deduplication;
- fewer than 10 of 12 exact Runtime actions;
- fewer than 9 of 12 exact five-attribute tuples;
- any attribute accuracy below 10 of 12;
- fewer than 5 of 6 intended counterfactual changes are recovered;
- evidence-reference coverage is below 100%;
- private labels leak into the prompt;
- a Provider relation or action enters canonical state;
- one logical call exhausts two physical attempts.

## Anti-Additive Audit

This experiment does not add:

- a new relation state;
- a second Runtime;
- a transform-name classifier;
- a Provider action field;
- a CoreSlim integration;
- a retention policy.

It adds only a standalone fresh corpus, an attribute receipt canonicalizer, a
scorer, and a bounded CLI. The existing Provider adapter and v0.3F compiler are
reused.
