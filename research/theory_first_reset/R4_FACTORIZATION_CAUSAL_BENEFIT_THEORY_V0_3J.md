## Research Object

`FACTORIZATION_CAUSAL_BENEFIT`

Does replacing one overloaded transformation enum with two orthogonal axes
increase Provider-supported latent-state and revalidation resolution without
increasing harmful Runtime actions?

Object chain:

```text
same fresh evidence cases
  -> legacy or factorized semantic schema
  -> Provider attribute receipts
  -> Runtime contract validation
  -> arm-specific deterministic compiler
  -> relation, action, and revalidation trajectory
```

## Compared Arms

### Legacy

Attributes:

- `SourceIdentity`;
- `LineageCoupling`;

- `TargetClaimRelation`.

### Factorized

Attributes:

Both arms receive identical public evidence statements and case-local evidence

## Legacy Projection

The private factorized truth projects to the legacy enum deterministically:

| Factorized pair | Legacy value |
| --- | --- |
| verified + global equivalent | verified global equivalence |
| verified + claim equivalent | verified claim equivalence |
| verified + reducing | information reducing |
| verified + augmenting | information augmenting |
| no transform + not applicable | not applicable |
| asserted-unverified + unknown effect | unverified transform |
| unknown applicability + unknown effect | unverified transform |

The final two latent states collapse into one legacy value. Therefore the
legacy schema cannot uniquely recover their distinct revalidation trajectory.
This ceiling is measured separately from Provider accuracy.

## Revalidation Trajectory

Runtime derives:

| Transform status | Next semantic validation |
| --- | --- |
| verified transform | `NO_TRANSFORM_STATUS_REVALIDATION` |
| no transform | `NO_TRANSFORM_RELATION_ESTABLISHED` |
| asserted unverified | `VERIFY_ASSERTED_TRANSFORM` |
| unknown applicability | `DISCOVER_TRANSFORM_APPLICABILITY` |

Legacy `UNVERIFIED_TRANSFORM` can derive only:

`TRANSFORM_STATUS_UNRESOLVED`

This is not an immediate composition action. It records the next cognition
required to reduce residual uncertainty.

## Leading Model

`M1_FACTORIZATION_CAUSAL_BENEFIT`

The factorized arm will improve exact latent transformation-state and
revalidation resolution by at least two of twelve cases relative to the legacy
arm, while preserving zero false deduplication.

Predictions:

- shared attributes remain comparably accurate across arms;
- factorized transform status and information effect remain inferable;
- factorized latent-pair exactness exceeds legacy unique resolution;
- factorized revalidation accuracy exceeds legacy;
- Runtime action accuracy does not degrade;
- factorized receipts cost more tokens, but remain within the frozen budget.

## Rival Models

### M0_NO_CAUSAL_BENEFIT

Both schemas produce equivalent latent resolution and action safety. The extra
axis adds vocabulary without useful information.

### M2_COMPLEXITY_HARMS_INFERENCE

The factorized schema lowers Provider exactness enough to erase its
representational advantage or creates false deduplication.

### M3_REPRESENTATIONAL_GAIN_ONLY

The factorized schema has a higher theoretical ceiling, but the Provider cannot
reliably populate it. Observed latent and revalidation resolution do not
improve.

### M4_ACTION_EQUIVALENCE_IS_SUFFICIENT

If both arms produce the same immediate action, semantic and revalidation
differences have no operational value.

This rival is weakened if factorization correctly selects distinct next
validation trajectories while immediate actions remain equal.

### M5_PRESENTATION_OR_TIME_DRIFT

An apparent arm difference is caused by case order or call timing. Two rounds
with reversed case and arm order test this rival.

## Experimental Design

Twelve fresh cases are presented in four independent batch calls:

1. legacy, forward order;
2. factorized, forward order;
3. factorized, reverse order;
4. legacy, reverse order.

Call order:

`L-F-F-L`

The second round reverses both arm and case order.

## Primary Metrics

- shared-attribute accuracy;
- legacy `InformationRelation` accuracy;
- factorized `TransformStatus` and `InformationEffect` accuracy;
- exact latent-pair resolution;
- exact revalidation trajectory;
- Runtime relation and action accuracy;
- false combine, false deduplicate, and false block;
- within-arm forward/reverse agreement;
- evidence-reference binding;
- tokens per receipt.

## Falsification Conditions

Reject M1 if any occurs:

- factorized latent-pair resolution fails to exceed legacy by at least 2/12 in
  both rounds;
- factorized revalidation accuracy fails to exceed legacy by at least 2/12 in
  both rounds;
- any factorized attribute is below 10/12;
- factorized Runtime action accuracy is below 11/12;
- any false deduplication occurs;
- within-arm action agreement is below 11/12;
- evidence-reference coverage is not exact;
- total calls or tokens exceed budget.

bounded CLI. It adds no production module, relation state, Runtime action,
retention policy, or CoreSlim integration.
